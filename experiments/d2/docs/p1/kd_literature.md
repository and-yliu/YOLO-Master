# 文献对照：特征蒸馏的权重、损失形式与空结果

> 本文是 [`kd_gradient_analysis.md`](kd_gradient_analysis.md) 的外部佐证。
> 那份文档从本仓库的实测出发，本文从已发表工作出发，两者独立得到同一结论。
>
> **核查状态标注**：`[已核实]` = 本人抓取原文并引用；`[未核实]` = 有引文但未经对抗性验证，按线索看待。

## 1. 权重脱离归约方式就没有意义

已发表的特征蒸馏权重按**归约方式**分成两簇，簇内高度一致：

| 方法 | 归约方式 | 权重 | 状态 |
|---|---|---|---|
| MGD | MSE 对 C·H·W 求和，仅除以 batch | 2e−5 | `[已核实]` |
| FGD | 对通道与空间位置求和 | 1e−3 … 5e−7 | `[已核实]` |
| **PKD** | **逐元素均值 (1/2m)，m = b·h·w** | **6 – 10** | `[已核实]` |
| **SP-KD** | **Gram，对 b² 对求均值，平方 Frobenius** | **2000 – 3000** | `[已核实]` |
| **RKD** | **Huber，距离先除以 batch 内平均距离** | **25 – 100** | `[已核实]` |
| **本仓库现状** | **Gram，对 B·N² 对求均值，L1** | **0.05（扫描至 4）** | — |

**凡是求均值的损失，权重都在 1 以上；凡是求和的损失，权重都远小于 1。**
本仓库的 relational 损失属于前者，却用了后者量级的权重。

> **归约方式与权重的因果关系已被对抗性核验通过。** FGD 与 MGD 的
> 「求和归约 ⇒ 权重必须远小于 1」两条，各以 3–0 全票确认。
> 其中 FGD 那条在第一轮曾以 1–2 被判否，重跑后翻转为 3–0 确认——
> 记录这次翻转本身：单轮投票不足以定论，这也是把票数写进文档而非只写结论的理由。
>
> 同时有一条被**否决**（1–2）并因此**未**写入本文：
> 「MGD 声称权重不是敏感超参」。权重不敏感这一点在本文只由 PKD 的实测扫描支撑。

最接近的对照是 SP-KD：同样是 Gram 矩阵、同样除以对数。
Tung & Mori 在 CIFAR-10 用 `γ = 3000`、CINIC-10 用 `2000`，由留出验证集选定，
并报告在很宽的 γ 范围内稳健。`[已核实]`

> ℒ_SP = (1/b²) Σ ‖G_T − G_S‖²_F，γ = 3000

**反向的好消息**：归约方式定下来之后，权重精度是二阶问题。
PKD 把 α 在 {3, 5, 8, 10, 13} 上扫描，COCO mAP 仅在 41.0–41.3 之间波动
（4 倍范围内相差 0.3 mAP）`[已核实]`。
因此梯度比探针不需要精确，只需落在正确的数量级上。

## 2. 损失形式决定梯度是否"知道自己错多少"

| 方法 | 残差上的函数 | 接近匹配时的梯度 |
|---|---|---|
| SP-KD | 平方 Frobenius 范数 | 趋零，完全与损失值耦合 |
| RKD | Huber——小残差处为二次 | 近零处收缩；仅在远处退化为符号 |
| FGD 全局项 | 关系特征的平方差 | 与损失值耦合 |
| **本仓库现状** | **纯 `.abs()`** | **恒定，永不收敛** |

Huber 的设计意图值得注意：它**刻意**在大残差处呈 L1 形态（鲁棒性），
但在原点附近是二次的。本仓库的 `.abs()` 等于把 Huber 的远场行为用到了全域，
包括最需要梯度随收敛而衰减的那一段。

RKD 另外把距离除以 batch 内平均距离，专门处理师生尺度失配，
并报告这带来"更稳定、更快的收敛"。`[已核实]`

一处诚实的复杂性：社区广泛使用的 RKD 复现用 `F.smooth_l1_loss`
配 PyTorch 默认的 mean 归约，即同样是"对所有 pair 求均值"`[未核实]`——
说明这个模式是常规做法。但 `smooth_l1` 在 |x| < 1 时仍是二次的，
保留了纯 `.abs()` 丢掉的那部分值耦合。

## 3. 损失值比是错的仪表，梯度范数比才是对的

- **GradNorm**：前提即"任务的支配地位体现在梯度幅值而非损失值上"，
  直接在共享层上调各任务梯度范数；α = 0 时退化为**等梯度范数**目标。`[未核实]`
- **MetaBalance**：给出可直接实现的辅助项缩放规则 `[未核实]`——

  > G_aux ← (G_aux · ‖G_tar‖ / ‖G_aux‖) · r + G_aux · (1 − r)
  >
  > r = 1 为严格梯度范数等同，r = 0 为不干预。

  并论证单一固定标量不可能处处正确：梯度失衡在**同一网络的不同部位**不同，
  且随训练漂移。

### 一条需要警惕的引用

**MoKD** 看起来是完美佐证：它命名了 "Gradient Dominance" 与 "Gradient Conflict"，
且有抽取到的说法称其在 COCO 检测上实测 ‖g_dist‖/‖g_task‖，发现任务梯度支配达 **1000 倍**。

**该论文已于 2025-08-02 撤稿**（理由："Major changes to the paper and the authorship"），
无 PDF 可取。`[存疑]` 摘要确实包含 GrD/GrC 框架与 ImageNet-1K + COCO 实验，
但那个 1000 倍的具体数字建立在已撤稿的预印本上，**不应引用**。

## 4. 对小检测器到底有没有用

### 朴素特征模仿是已记录的近似空结果

COCO 上 FitNet 式同层特征模仿：+0.87 mAP（R18-FPN）、+0.83（R50-FPN）、
+0.73（MobileNetV2-FPN）、+0.15（RetinaNet-50）`[未核实]`；
另一篇（DiffKD 表 4）报告 FitNet 把 RetinaNet-R50 从 **37.4 AP 变成 37.4 AP——零增益**、
Faster R-CNN-R50 从 38.4 到 38.9（+0.5），而 DiffKD 在同表达到 39.7 与 40.6。`[已核实]`

真正拿到 +3～+4 mAP 的方法（MGD、FGD、PKD）全部使用**同族大教师**、
完整 2× COCO 训练表、约 25M 参数的学生。没有一个是"冻结基础模型教 YOLO 级 backbone"。

### 与 D2 最接近的已发表实验是混合偏负结果

冻结 DINOv2 蒸馏进 FairMOT 的 HRNetv2-W18，20 epoch：`[已核实]`

| 数据集 | MOTA | IDF1 |
|---|---|---|
| MOT17 | 81.8 → 84.7（+2.9） | 82.9 → 86.5（+3.6） |
| MOT20 | 71.5 → 69.6（−1.9） | 64.0 → 61.9（−2.1） |
| DanceTrack | 65.4 → 65.6（+0.1） | 34.9 → 33.1（−1.8） |
| Fish（私有） | 27.3 → 25.6（−1.7） | 41.8 → 39.4（−2.4） |

**一个数据集涨，三个数据集跌。** 作者自己的解释值得 D2 重视：
教师全程不更新，其特征可能**对该任务过于通用**，而学生 backbone 可以自由特化。
冻结的基础模型未必是检测任务的合适教师。

### 对判读线的影响

§6 的 no-go 线是 |Δ mAP50-95| < 0.003（0.3 个百分点）。
若朴素特征 KD 在**25M 参数**、教师匹配良好的条件下真实效应就只有 0～+0.9 mAP，
那么在 YOLO-n 规模、`coco128` 上，真实效应很可能落在判读线**之下**，3 个 seed 无法分辨。

这不是反对跑 P1，而是主张**提前声明**：本预算下的空结果将无法区分
「无效应」与「功效不足」。应当现在就写定，什么证据才能把这两者分开。

## 5. 有名字的失效模式

- **投影器吸收信号。** DINOv2→FairMOT 中，更简单的单层 conv + 双线性投影器
  胜过更深的 conv+BN+ReLU（MOTA 50.0 vs 47.8）`[已核实]`——投影器容量更大反而更差。
  TinTeM 进一步主张学生侧投影器会"包含复现教师网络的信息并扭曲学生自身的输出"，
  改为在**教师侧**放冻结的近正交头，把教师特征降到学生维度。`[未核实]`
- **特征幅值失配劫持梯度。** PKD 的动机原文：幅值大的 FPN stage
  "会支配蒸馏损失的梯度，压过其他特征的作用"`[已核实]`；其对策是逐通道 z 归一化使目标尺度无关。
- **学生容量才是约束。** 有工作报告朴素特征对齐在小 ViT 上只带来 +0.21% top-1，
  并诊断为"编码失配"：教师每个 token 的能量铺满约 90% 通道，窄学生无法实现该编码，
  与投影器无关；其对策是加宽而非调权重。`[未核实]`
  **这正是探针 B 要检验的假设。**

### 实践中使用的诊断

1. 共享参数上的**梯度范数比** ‖g_aux‖/‖g_task‖——即探针 A。
2. **梯度冲突**：⟨g_dist, g_task⟩ 的符号，为负说明 KD 项在与检测目标对抗。
   两个梯度反正都要算，加这一项零成本，且能区分「太弱」与「在打架」——两者对策相反。
3. **梯度幅值相似度** Φ = 2‖g_i‖‖g_j‖/(‖g_i‖²+‖g_j‖²)，等同时为 1，被支配时趋 0。`[未核实]`
4. **与同预算未蒸馏基线做 A/B**——mmrazor 的一个 issue 中，实践者正是这样
   发现配置灾难（mIoU 0.07 vs 0.27），而不是靠看 KD 损失曲线。`[未核实]`
   **一般教训：KD 项出现在日志里并且在下降，不构成它有用的证据。**

## 6. 对 D2 计划的三处修正

1. ~~**放宽探针 A 的预期区间。** `w*` 应预期落在数十到数千量级，而非个位数。~~
   **已被实测推翻**：探针 A 实测 `w* = 3.90`（10% 梯度份额目标）。
   把 SP-KD 的 γ=3000 当作可迁移先验是错的——它的 Gram 建在样本对上、用平方 Frobenius、
   任务损失是交叉熵，与本仓库不同尺度。**归约方式给簇，不给值。**
   见 [`kd_gradient_analysis.md §6.5.1`](kd_gradient_analysis.md)。
2. **加入冲突检查。** 与范数一起测 ⟨g_dist, g_task⟩，零额外成本。
   **已实施并已产出关键结果**：实测 cosine ≈ −0.0095、53% 的 batch 内积为负，
   即 KD 梯度与任务梯度**近乎正交**。这在一阶上解释了为什么任何权重都不会
   使检测损失劣化——正交更新不改变任务损失，因此 §5.5.1 的准则结构上无法选出 `w`。
   本条是本轮唯一由文献建议、实测兑现的诊断。
3. **锁权重之前先重新考虑损失形式。** 在唯一直接可比的实验里，
   尺度无关的 cosine 式目标比 MSE 高 2.0 MOTA；`foundation_loss` 已支持
   `cosine` 与 `hybrid`，本机实测梯度约 8 倍，且与 `.abs()` 不同，会随收敛衰减。纯配置改动。

外加一处零成本的表述修正：在 P1 开跑前声明真实效应可能低于判读线，
把一个大概率含糊的空结果，变成预注册的预期而非事后的失望。
