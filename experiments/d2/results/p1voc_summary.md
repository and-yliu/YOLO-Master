## 3. 分析

### 3.1 A：唯一方向一致的格

三个 seed 的配对差值 `[+0.0073, +0.0040, +0.0027]` **全部为正**，`t = +3.40`。
但 n=3 的双侧 p ≈ 0.077，CI 下沿 `−0.0012` 仍在 0 的负侧。

**按判读线这不是 go，也不是 no-go。** 三选一的结论是「加 seed」：
按实测 `sd = 0.00238` 外推，**n=4 即可使 CI 排除 0**（前提是均值与方差保持不变——恰恰是 3 个 seed
撑不起的假设）。保险起见按 **n=5** 规划，即 off 与 A 各补 2 个 seed，共 4 个 run ≈ **73 h**。

值得注意的是 **off 三个 seed 极其集中**（0.4724 / 0.4744 / 0.4771，极差 0.0047），
说明这条配对设计的噪声底本身很低，这也是 n=4 就可能够用的原因。

### 3.2 C 变差，但有一处必须先查清的干扰

C 三个 seed 全部低于 off，且 **C − A 的配对差 `−0.0117`（t = −3.69，CI `[−0.0254, +0.0020]`）三 seed 同号**——
「SigLIP2 不如 DINOv3」是本批数据里方向最一致的信号，且这条轴（A↔C）是设计上最干净的一条：
两侧都是 patch-16、都零插值。

**但不要现在就下这个结论**，因为 KD 的实际份额三格并不相等：

| 格 | `foundation_loss_weight` | `task_ratio` 列（e5→e400 稳定值） | **换算后的真实份额** |
|---|---|---|---|
| A | 3.6859 | ≈ 0.24 ~ 0.25 | **≈ 8.4%** |
| B | 2.7095 | ≈ 0.17 ~ 0.18 | ≈ 6.1% |
| C | 3.1107 | ≈ 0.10 ~ 0.12 | **≈ 3.8%** |

**`foundation_task_ratio` 这一列不能按字面读成「KD 占任务损失的比例」，它偏大 3 倍。**
定义在 `foundation_distill_model.py:1017`：

```python
task_scalar = float(task_loss.detach().float().mean().item())
...
"foundation_task_ratio": foundation_scalar / max(task_scalar, 1e-8),
```

- **分子** `foundation_scalar` = `feature_loss + route_loss + semantic_loss`，其中
  `feature_loss = kd × effective_weight × batch_size`——**已经乘过权重和 batch**。
- **分母** `task_scalar` 取的是 `task_loss` 的 `.mean()`。而 `task_loss` 来自
  `v8DetectionLoss.loss`（`utils/loss.py:491`），返回的是 **`loss * batch_size` 这个 3 元向量**
  （box / cls / dfl），不是标量。**对 3 元向量取 `.mean()` = 三项之和 ÷ 3。**

真正被优化的目标是三项之**和**——`foundation_distill_model.py:1047` 把两者
`torch.cat` 成一个向量交给 trainer 求和（不是相加广播，所以没有重复计权）。
因此这一列的分母只有实际检测目标的 1/3，**列值 ÷ 3 才是 KD 占检测损失的份额**。

实测核对（末 epoch，12 个 run）：用 `(box+cls+dfl)/3 × 64` 作分母可复现日志值，误差 < 0.8%；
用 `(box+cls+dfl+aux)/4 × 64` 误差 10%。**故 MoE `mixture_aux` 不在分母内**——
若把它算进检测目标，上表的真实份额还要再低一档。

**这个口径问题不需要重跑任何 run。** 两条理由：

1. **该指标是纯日志量。** `task_scalar` 在文件中只出现两次：从 `.detach()` 的张量取 `float()`，
   然后写进 `_last_foundation_metrics`。它**从不进入返回的 loss**
   （返回的是 `torch.cat([task_loss, foundation_loss])`）。改它不可能改变训练，
   同 seed 重跑会得到逐位相同的结果。
2. **换算是精确的，不是估计。** 对 3 元向量，`mean = sum / 3` 恒成立，所以
   `新值 = 旧值 ÷ 3` 对每一个已归档的数值**精确成立**，与向量里有没有 aux 无关。
   （前提是 detect 头的 3 分量；segment/pose 的除数不同，D2 全部是 detect。）

> **真正会强制重跑的是另一件事**：`mixture_loss.py:416` 的 `total = native_loss + aux`
> 把标量广播到分量向量上，`.sum()` 因此把 aux 算了 3 次。那条**改的是训练**，
> 一旦修就与现有全部 run 不可比。**不要在本批实验中途动它。**

A 与 C 之间 **2.2 倍**的落差不受这个换算影响（分母口径一致），所以下面的混杂论证照旧成立；
受影响的只是「谁偏离得多」——**是 C 偏低，不是 A 偏高**。

#### 换算后并不等于「达到了 10%」——两者根本不是同一个量

必须避免一个顺理成章的误读：**修好这一列并不会让任何一格变成 10%，也不该期待它变成 10%。**

- **预注册的 10% 是梯度份额**：`kd_gradient_probe.py` 解的是 `‖g_kd‖ / ‖g_task‖ = 0.1`，
  其中 `g_task` 来自 `loss[:-1].sum()`（`kd_gradient_probe.py:234`）。
- **日志里的这一列是损失值之比**。两者都是无量纲比值，但测的不是一回事。

探针其实**已经记录下了这个差距**，只是当时归因于「损失比 ≠ 梯度比」：

```json
"loss_ratio_vs_gradient_ratio_at_w1": {
  "foundation_task_ratio": 0.094115,
  "gradient_norm_ratio":   0.025652,
  "loss_ratio_overstates_by": 3.67
}
```

修复之后这个 **3.67 正好可以拆开**：

```
3.67  ≈  3（分母取 mean 而非 sum 的口径错误）  ×  1.22（损失比与梯度比的真实差异）
```

即 `0.094115 / 3 = 0.0314` 对 `0.0257`——**修复把 3.67 倍的偏差压到 1.22 倍**。
这才是这次修复的实际收益：**这一列第一次可以当作梯度份额的粗略代理来用**，
而不是第一次「对齐到 10%」。

若把 1.22 这个系数外推到 P1（**这是外推，不是测量**——它测于 `w=1`、训练起点、coco128、
且只对 DINOv3），三格的**隐含梯度份额**是：

| 格 | 修正后损失份额 | ÷ 1.22 → 隐含梯度份额 | 标定意图 |
|---|---|---|---|
| A | 8.4% | ≈ 6.9% | 10% |
| B | 6.1% | ≈ 5.0% | 10% |
| C | 3.8% | ≈ 3.1% | 10% |

**三格都低于标定意图，且低的程度不同。** 但这一整列是外推得到的，
真正的训练中梯度份额**至今没有被测过**（checkpoint 不含 projector，见上）。
所以正确的说法是：**「没达到 10%」是一个有依据的怀疑，不是一个测量结果。**

这也让 §5.4 归因清单上「份额目标取小了」这一条**进一步上升**——
不只是目标可能定低了，实际交付的可能还低于那个目标。

> **注意：中期 checkpoint 探针这条路走不通。** `last.pt` 里只有 `model.*`（学生）与
> `train_args`，**不含 projector 权重**（已核对 `a-s17/weights/last.pt` 的 pickle 字符串表）。
> 重新包一层 wrapper 会拿到**随机初始化的 projector**，测出来的仍是 t=0 的梯度比，
> 不是训练中期的。要测中期份额只能在训练里埋点，或先把 projector 存进 checkpoint。

### 3.2.1 一条更省事的竞争性解释：三格的差异可能只是「剂量」

把权重和实测的 KD 原始损失放在一起看，三格拿到的**实际剂量**是单调递减的：

| 格 | `relational_raw`（末 epoch 均值） | `w` | 加权剂量 `w × raw` | 换算份额 | **Δ mAP50-95** |
|---|---|---|---|---|---|
| A | 0.04860 | 3.686 | **0.1791** | 8.4% | **+0.0047** |
| B | 0.04871 | 2.709 | 0.1320 | 6.1% | +0.0028 |
| C | 0.02693 | 3.111 | 0.0838 | 3.8% | −0.0071 |

**剂量与效应完全同序。** 这个排序既能被「DINOv3 优于 SigLIP2 且单尺度优于多尺度」解释，
也能被「KD 剂量越大越好、教师与尺度都是附带的」解释——**当前数据无法区分这两者**，
而后者不在 §5.4 的归因清单上。

尤其刺眼的是 **A 与 B 的教师相同**（DINOv3），实测 `relational_raw` 几乎相等
（0.04860 vs 0.04871），**但标定给了它们相差 36% 的权重**（3.686 vs 2.709）。
也就是说，在「只变尺度」这条轴上，标定**凭空引入了 26% 的剂量差**。
B 判 no-go，可能只是因为它被喂得比 A 少。

`1.4` 的权重扫描扫的是**检测损失**是否劣化，从未扫过 **mAP 随 w 如何变化**——
所以「剂量单调」这条解释至今没有任何数据反驳它。

另外 C 的 s43（`−0.0152`）是 s17/s29（`≈ −0.003`）的 5 倍，单点主导了整格方差
（`sd = 0.0070`，是 A/B 的 3 倍）。C 目前**既没有稳定的效应量，也没有干净的归因**。

### 3.3 B：判 no-go，且多尺度没有带来增益

B 的均值 `+0.0028` 落在 ±0.003 零带内且 CI 跨 0 → **按预注册规则判 no-go**。
B − A 的配对差为 `−0.0019`（CI `[−0.0062, +0.0025]`），**多尺度相对单尺度 P4 没有可测的增益**，
方向上还略负。

结合 §2.4 的已知混杂，这条**恰好不需要解开**：多尺度既没有变好也没有变坏，
所以「是多尺度没用还是插值拖累了」这个二选一**暂时不必回答**——两种解释都指向「别做多尺度」。

### 3.4 与 COCO 首对的关系

COCO 那对给出 `Δ = −0.0060`（n=1，且跑在未标定的 `w=3.0` 上）。
VOC 的 A 格给出 `+0.0047`（n=3，标定权重）。**两者不可相减**（§5.2），
但可以说一句：**COCO 那个负号没有在 VOC 上复现**，它作为 n=1 观测本就不构成结论，现在也不必再解释它。

## 4. 为什么放弃 D

D 是**交互格**，两条轴同时移动，设计上就规定了「只能与 B、C 联合解读」（§2.1）。
它的价值完全取决于 B 和 C 是否各自给出可归因的效应：

- **B 判 no-go** —— 多尺度这条轴上没有需要解释的效应；
- **C 无干净归因** —— 教师轴上的负向差异先被 §3.2 的份额问题挡住。

两个边际都不成立时，D 的交互项**没有可对照的主效应可依附**，跑出来的任何数字都无法归因。
再加上 D 是「最贵的教师 × 最贵的尺度」组合，按 C（28.2 h）与 B（21.4 h）的单价推算,
三个 seed 约需 **90 h**，是当前最差的信息/成本比。

**结论：D 记为 `dropped`，理由写入矩阵，不删除行与配置**——保留 provenance，
`validate_pair.py` 的五配置一致性校验也继续有效。若 C 在澄清份额后重新出现稳定效应，D 可以再启。

### 5.1 为什么不建议「换成 constant w 再跑一轮」

constant w 只对**一条轴**是更好的控制，对另一条无效：

- **A↔B（尺度轴，同教师）**：两格 `relational_raw` 几乎相等，constant w 会让剂量几乎相等
  （w=3.9 时 0.1895 vs 0.1900）。**这条轴上 constant w 明显优于现在的逐格标定**，
  因为标定在这里制造了 36% 的权重差却没有对应的损失尺度差。
- **A↔C（教师轴）**：两个教师的 KD 损失尺度天生差 1.8 倍（0.0486 vs 0.0269）。
  constant w 下剂量仍差 1.8 倍（0.1895 vs 0.1050），逐格标定下差 2.1 倍。
  **两种做法都没有对齐剂量**，换过去并不能让教师轴变干净。

所以 constant w 不是「更严格的对照」，而是「换一个同样没对齐的口径」，
代价却是整个矩阵重跑。**真正要控的是交付剂量，而不是 w 这个旋钮**，
而剂量只能实测、不能在 t=0 预测——这正是 §3.2.1 建议做剂量梯度而非重跑矩阵的原因。

## 6. 本文不主张什么

- **没有主张 KD 有用。** A 是 inconclusive，不是 go。三个 seed 同号是提示，不是证据。
- **没有主张 SigLIP2 比 DINOv3 差。** 该对照被 §3.2 的份额差异干扰，尚未排除。
- **没有移动判读线。** ±0.003 与「CI 需排除 0」自 `design.md` 2.2 提交以来未改。
- **`seeds_needed` 的外推不是承诺。** 它假设 3 个 seed 测出的均值与方差成立，
  而这正是 n=3 撑不起的假设。
- **没有主张 KD 份额已经调对，也没有主张修复让它对齐到了 10%。**
  10% 是**梯度**份额目标，日志列是**损失**比；修复只把两者的偏差从 3.67 倍降到 1.22 倍。
  「三格都低于目标」是基于 1.22 外推的**怀疑**，训练中的梯度份额从未被实测。
- **`tail5` 不是为了让结果好看。** 三种取法（`last`/`best`/`tail5`）判读完全一致，见 §1。
- **D 的放弃是成本决策，不是结果。** 没有 D 的数据，也就没有关于交互项的任何主张。
- **没有主张「剂量单调」是真的。** §3.2.1 只是一条当前无法被排除的竞争性解释，
  三个点、每点一组 seed，既不能证实也不能证伪——它的作用是把「教师/尺度」的结论**降级为待定**。
